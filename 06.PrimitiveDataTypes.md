
# Types of Variables (Based on Data Type)

## 1. Primitive Types

* byte
* short
* int
* long
* float
* double
* char
* boolean

Primitive variables store **actual values**.

---

## 2. Reference (Non-Primitive) Types

* String
* Arrays
* Classes
* Interfaces
* Enums
* Objects

Reference variables store the **memory address (reference)** of an object.

Example:

```java
String name = "Priya";
```

---

# Primitive Data Types

| Data Type | Size              | Description       | Range / Values        |
| --------- | ----------------- | ----------------- | --------------------- |
| byte      | 1 byte (8 bits)   | Signed integer    | -128 to 127           |
| short     | 2 bytes (16 bits) | Signed integer    | -2¹⁵ to 2¹⁵−1         |
| int       | 4 bytes (32 bits) | Signed integer    | -2³¹ to 2³¹−1         |
| long      | 8 bytes (64 bits) | Signed integer    | -2⁶³ to 2⁶³−1         |
| float     | 4 bytes (32 bits) | Floating point    | ~6–7 decimal digits   |
| double    | 8 bytes (64 bits) | Floating point    | ~15–16 decimal digits |
| char      | 2 bytes (16 bits) | Unicode character | '\u0000' to '\uffff'  |
| boolean   | JVM dependent*    | true / false      | true or false         |

> **Note:** Although `boolean` is conceptually true/false, the Java Language Specification **does not define its storage size**. It is often implemented efficiently by the JVM, but it is **not officially "1 bit"**.

# Why is char 2 Bytes?

Java uses **Unicode (UTF-16)** to support characters from multiple languages.

Example:

```java
char ch = 'A';
char hindi = 'अ';
char emoji = '\u263A';
```

# Float vs Double

### Float

* 32-bit
* Precision: ~6–7 decimal digits
* Requires **f** or **F** suffix

```java
float f = 3.14f;
```

Without the suffix:

```java
float f = 3.14;    // ❌ Error
```

because decimal literals are **double** by default.

---

### Double

* 64-bit
* Precision: ~15–16 decimal digits
* Default type for decimal literals

```java
double d = 3.14;

double d2 = 3.14d;   // 'd' suffix is optional
```

---

# Why Shouldn't We Use float/double for Money?

`float` and `double` follow the **IEEE 754 floating-point standard**. They store numbers in **binary (base-2)** rather than **decimal (base-10)**.

Many decimal values (like 0.1 or 0.2) **cannot be represented exactly in binary**, which causes rounding errors.

Example:
System.out.println(0.3f - 0.1f);
Output:
0.20000002 instead of 0.2

Therefore, For financial or currency calculations, use: **BigDecimal** instead of float or double.
